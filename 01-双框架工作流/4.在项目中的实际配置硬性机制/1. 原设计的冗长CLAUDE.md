# CLAUDE.md

> 本文件定义 Matt Pocock Skills 与 Superpowers Skills 双框架在本项目中的分工规则、触发边界与冲突处理方式。所有 Agent 行为必须遵守以下条款。

---

## 一、总体原则

**Matt 负责“想清楚”，Superpowers 负责“做扎实”。**

- 需求、领域建模、架构决策、bug 分诊 → 走 Matt Pocock Skills
- 执行骨架、TDD、审查、验证、收尾 → 走 Superpowers Skills
- 当两套技能都能处理当前阶段时，按本文件第三节的规则二选一，不得随机触发。

---

## 二、安装与项目结构

- **Superpowers 层**：通过插件市场安装，全局生效，不占项目目录。
- **Matt 层**：通过 `npx skills@latest add mattpocock/skills` 安装到项目内，提交 Git，按项目定制。
- **Matt 技能目录**：`.claude/skills/matt/`
- **文档与工单目录**：`.scratch/<feature-slug>/`
- **首次使用**：每个仓库运行一次 `setup-matt-pocock-skills`，配置 issue tracker、triage 标签、文档目录。

**不得平铺两套技能。** 两层通过安装方式隔离（插件 vs 项目内），通过本文件明确优先级（需求走 Matt，执行走 Superpowers）。

---

## 三、重叠技能的分工规则（全量保留，逐条声明）

不删除任何技能。以下重叠技能逐条声明归属，Agent 必须严格遵守。

### 3.1 需求澄清

- 只使用 Matt 的 `grill-me`
- **不使用** Superpowers 的 `brainstorming`
- 例外：仅当 `grill-me` 不可用或用户明确要求时，才允许临时切换，且必须在回复中说明原因。

### 3.2 TDD

- 只使用 Matt 的 `tdd`
- **不使用** Superpowers 的 `test-driven-development`
- 二者只能选一个，不得同时触发，不得互相推诿。

### 3.3 调试

- 复杂问题（多组件、跨模块、根因不明、已尝试多次修复未果）→ 走 Matt 的 `diagnosing-bugs`
- 简单问题（单一文件、错误信息明确、可快速复现）→ 走 Superpowers 的 `systematic-debugging`
- 若 Agent 无法判断复杂度，默认走 `diagnosing-bugs`。

### 3.4 执行骨架

- 执行、审查、验证、收尾全部走 Superpowers 执行骨架：
  `using-git-worktrees` → `subagent-driven-development` / `executing-plans` → `requesting-code-review` → `receiving-code-review` → `verification-before-completion` → `finishing-a-development-branch`
- Matt 的 `tdd` 嵌入执行骨架内部，不替换执行骨架。

---

## 四、触发方式约束

触发不靠安装方式，靠本文件的规则约束。

### 4.1 Matt 层：手动触发为主

- `grill-me`：用户主动调用，或由 `to-prd` 上游触发
- `domain-model`：对话中自动提取，但结果需用户确认
- `to-prd` / `to-issues`：用户主动调用
- `improve-codebase-architecture`：用户主动调用
- `design-an-interface` / `request-refactor-plan`：用户主动调用
- `triage-issue` / `diagnosing-bugs`：用户报告 bug 时触发

### 4.2 Superpowers 层：自动触发为主

- `using-superpowers`：会话启动时 hook 自动注入
- `using-git-worktrees`：进入实现阶段自动触发
- `subagent-driven-development` / `executing-plans`：有完整计划后触发
- `requesting-code-review` / `receiving-code-review`：任务间触发
- `verification-before-completion`：声称完成前触发
- `finishing-a-development-branch`：所有任务完成、测试通过后触发

### 4.3 强制声明

- 需求澄清阶段只使用 Matt 的 `grill-me`，不使用 Superpowers 的 `brainstorming`。
- TDD 阶段只使用 Matt 的 `tdd` 或 Superpowers 的 `test-driven-development`，二者只能选一个（本项目选 `tdd`）。
- 调试阶段优先使用 Matt 的 `diagnosing-bugs`，简单问题可以用 Superpowers 的 `systematic-debugging`。

## 五、六层工作流

### 第 0 层：环境配置（一次性）

- 安装 Matt 和 Superpowers
- 运行 `setup-matt-pocock-skills`，配置 issue tracker、triage 标签、文档目录
- 运行 `setup-pre-commit`，配置提交前 lint、类型检查、单元测试
- 运行 `git-guardrails-claude-code`，拦截危险 git 命令
- 如需子代理开发，启用 Superpowers 多代理配置

### 第 1 层：模糊需求 → 清晰 PRD

- `grill-me`：盘问需求，走遍决策树
- `domain-model`：提取统一语言，建立领域词汇表
- `to-prd`：生成 PRD，发布到 issue tracker
- 不使用 `edit-article`
- 不使用 Superpowers 的 `brainstorming`

### 第 2 层：PRD → 可执行工单

- `to-issues`：拆成垂直切片，按依赖排序
- 每个 issue 包含验收标准、测试要求、依赖关系
- 复杂 issue 可再用 Superpowers 的 `writing-plans` 写局部微计划，不要每个都写

### 第 3 层：每个 issue 的执行循环

- `using-git-worktrees`：创建隔离工作区
- `subagent-driven-development` 或 `executing-plans`：执行任务
- `tdd`：TDD 循环（不使用 `test-driven-development`）
- `requesting-code-review`：任务间审查
- `receiving-code-review`：处理审查反馈
- `verification-before-completion`：完成前必须运行验证命令
- `finishing-a-development-branch`：合并、PR、保留或丢弃

### 第 4 层：测试检查阶段（质量门禁）

- 提交前：`setup-pre-commit` 自动跑 lint、类型、单元测试
- 任务完成：`tdd` + `verification-before-completion`
- 分支完成：全量测试 + `requesting-code-review`
- 端到端或浏览器：`agent-browser` 或 `webapp-testing`
- 失败诊断：`diagnosing-bugs`（复杂）或 `systematic-debugging`（简单）
- 人工验收：用户最终确认

### 第 5 层：修改与重构

**Bug 路径：**

- `triage-issue` → `diagnosing-bugs` → 修复 → 回到执行循环

**架构重构路径：**

- `improve-codebase-architecture` 发现候选
- `design-an-interface` 设计目标接口
- `request-refactor-plan` 制定计划
- `to-issues` 拆成工单
- 回到执行循环

**严禁混用：** `triage-issue` 是 bug 分诊，不是重构；`diagnosing-bugs` 是 bug 诊断，不是重构规划；`design-an-interface` 是重构子步骤。两条路径必须分开。

### 第 6 层：阶段完成

- `verification-before-completion`：确认所有验证命令通过
- `requesting-code-review`：最终代码审查
- 全量测试 + 人工验收
- `finishing-a-development-branch`：收尾

## 六、冲突处理

- 本文件第三节的分工规则优先级高于 `using-superpowers` 的默认触发规则。
- 当 `using-superpowers` 强制检查与 Matt 技能触发冲突时，以本文件第三节为准。
- 子代理不继承启动注入的上下文，若发现子代理跳过规则，手动触发 `using-superpowers` 将其拉回，并同时重申本文件第三节的归属声明。
- 如需临时停用 Superpowers 全套规则，用户可说“让我们跳过超能力”，但本文件第三节的分工规则仍然生效。

---

## 七、禁止事项

- 禁止两套框架平级同时强制
- 禁止每个 issue 都跑 Superpowers 七阶段全流程
- 禁止 `brainstorming`、`test-driven-development`、`systematic-debugging` 在未声明的情况下被自动触发
- 禁止 `edit-article` 用于 PRD、issue、代码文档
- 禁止 `domain-model` 放在初始配置阶段
- 禁止 Bug 分诊和架构重构混用技能
- 禁止测试检查阶段混在执行循环里，必须独立成层
