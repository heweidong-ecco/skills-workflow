## 一 · 这一层是什么

**问题**：把 Matt Pocock Skills 和 Superpowers 同时装进一个项目，
**最大的风险不是技能不够用，是两套框架互相争夺触发权。**

**核心主线**：**Matt 负责「想清楚」，Superpowers 负责「做扎实」。**

**关键手法：用「安装方式」做隔离** ——

| 框架 | 装法 | 为什么 |
|---|---|---|
| **Matt** | **项目内安装** | `setup-matt-pocock-skills` **本身就设计成 per-repo**（要配 issue tracker / triage 标签）⇒ 插件装会丢掉这个核心设计 |
| **Superpowers** | **插件安装**（全局） | `using-superpowers` 是 **hook 注入的全局行为** ⇒ 项目内装会导致技能复制 N 份 + 版本漂移 |

## 三 · ⚠️ 评估（**预测性判断，不是实测结论**）

> ### 📌 本节的来源：**人与 AI 协作产出的评估**（2026-09-17）
>
> **它是判断，不是实测结论** —— 所以单列一节，不与 `5. T07实测报告` 混。
> ⚠️ **本目录里唯一有实测的部分是 `5.`** —— 其余是设计与评估。
>
> （这个区分不是形式：这套工作流自己的实测就证明过 ——
> **「门禁的失效可以是静默的」，而「声称」和「做到」长得一模一样。**）

### 3.1 ⭐ 核心预测：差异不在「平均质量」，在「尾部」

| | 直接输出代码 | 有工作流 |
|---|---|---|
| **顺利时** | 差不多 | 差不多 |
| **出错时** | **静默** —— 错了没人知道 | **被拦下** |

**⇒ 价值是「砍尾部」，不是「抬平均」。**

**理由**：工作流**不改变模型能力**，它改变的是「**错了会不会被发现**」。
（这正是 `5. T07实测报告` 实测到的 —— **「放行」和「没人违规」长得一模一样**。）

### 3.2 ⚠️ 反向预测：**边际收益递减**

- **前几层**（需求澄清 / PRD / TDD / 验证）：**收益大** —— 直接决定「做对没有」
- **后几层**（每个 issue 全套七阶段）：**收益小、成本大**
- 依据：`3.` 自己写了 —— 「**每个 issue 都跑完整 Superpowers 七阶段，Token 会爆炸，进度会极慢**」

**⇒ 正确用法是「按风险选用」，不是「每步都跑」。**

### 3.3 精确结论

> **它「把下限抬高了」，不是「把上限抬高了」。**
> 因为质量的上限由「**澄清得够不够**」和「**验证得严不严**」决定 —— **不由层数决定**。

### 3.4 ⭐ 可能最不可替代的地方

**在「AI 协作」语境下，工作流的真正价值是「让人类能跟得上」**：

- AI 直接吐 500 行代码 ⇒ **人没法审**
- 工作流把过程**切成六层**，每层有**产出物**（PRD / issue / 审查记录 / 验证证据）⇒ **人能在每个节点介入**

**⇒ 它的价值不是「产出更好」，是「产出可被人类裁决」。**

### 3.5 ⚠️ 边界：**这套还没在真实项目上跑完过**

| | |
|---|---|
| ✅ **实测过的** | hook 的硬约束层（`5. T07实测报告`）—— 抗绕过 **1/5 → 5/5** |
| ⛔ **没跑过的** | **六层工作流在一个真实项目上的完整循环** |

**⇒ 所以「产出质量高」目前是预测，不是结论。**

## 四 · 实测摘要（**唯一有实测的部分**）

`5. T07实测报告` 的结论（2026-09-13）：

> **门禁的失效可以是「静默」的：不报错、不告警，只是放行。**
> **而「放行」和「没人违规」长得一模一样。**
>
> 本次实测复现了 **三个独立的静默失效层**，三层叠加使原包 **一个技能都拦不住**。

| 项 | 值 |
|---|---|
| 原包拦截率 | **0** |
| 修复后抗绕过 | **1/5 → 5/5** |
| 报告自带 | **可复现的 bash 命令**（三层逐层暴露） |
