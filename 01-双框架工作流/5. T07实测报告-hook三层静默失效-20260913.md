# T07 实测报告 · hook 的三层静默失效

- **日期**：2026-09-13
- **对象**：`4. 实施copy文件夹到项目/.claude/hooks/skill-guard.sh`（双框架工作流的硬约束层）
- **触发**：为核实「绕过率」一项，按 `00-运行前必做清单/4.工作流自动化测试执行方案.md` 实跑 L1
- **结论**：**原包在真实环境下拦截率为 0 —— 且不产生任何「门禁已坏」的信号。**

---

## 一、一句话结论

> **门禁的失效可以是「静默」的：不报错、不告警，只是放行。**
> **而「放行」和「没人违规」长得一模一样。**
>
> 本次实测复现了 **三个独立的静默失效层**，三层叠加使原包 **一个技能都拦不住**。

---

## 三、修复前：三层静默失效

### 第 1 层 · 权限 —— `exit 126`

```
$ ls -l .claude/hooks/skill-guard.sh
-rw-r--r--  1 ...                 # ← 无可执行位

$ printf '{"tool_input":{"skill":"brainstorming"}}' | ./.claude/hooks/skill-guard.sh
permission denied
→ exit 126（命令不可执行）
```

**后果**：hook 从不执行 → **全部放行**。

**注意**：`3.双框架工作流完整实施文档.md` 第 6 步明确写了 `chmod +x`，
**但打包成配置包时那一步没做** —— 实施文档与配置包不一致。

### 第 2 层 · locale —— `exit 1`（★ 最隐蔽）

脚本第 28 行（原文）：

```bash
echo "Blocked: ...禁止调用 $skill。需求澄清使用 grill-me，TDD 使用 tdd。" >&2
                                 ↑ 变量后直接跟中文句号
```

本机 `LANG=zh_CN.UTF-8`，bash 把 `。` 的字节并入了变量名：

```
.claude/hooks/skill-guard.sh: line 28: skill�: unbound variable
```

配合 `set -u` → **exit 1**。

**后果**：Claude Code 的 hook 退出码语义是——**只有 `exit 2` 阻塞**；
**`exit 1` 属于「非阻塞错误」** ⇒ **工具调用照常执行**。
**即使精确写 `brainstorming`，也拦不住。**

> 这一层最危险：**它的表现和「没人违规」完全一样**，没有任何告警。

### 第 3 层 · 匹配策略 —— 仅精确字符串

脚本用 `[[ "$SKILL_NAME" == "$skill" ]]` 做**精确匹配**。实测：

| 输入 | 结果 |
|---|---|
| `brainstorming` | exit 2 ✅ 拦住 |
| `Brainstorming` | exit 0 ⚠️ 绕过 |
| ` brainstorming ` | exit 0 ⚠️ 绕过 |
| `brainstorm` | exit 0 ⚠️ 绕过 |

## 四、修复内容

| # | 修复 | 说明 |
|---|---|---|
| 1 | `chmod +x .claude/hooks/skill-guard.sh` | 补上实施文档第 6 步漏掉的动作 |
| 2 | `$skill。` → `${skill}。` | 消除 locale 下的变量解析歧义 |
| 3 | 归一化 `tr '[:upper:]' '[:lower:]'` + 去前后空格 | 堵大小写 / 空格变体 |
| 4 | 禁止列表补别名 `brainstorm` | 堵别名变体 |
| 5 | 脚本头注释补 **退出码语义**说明 | 让下一个读它的人（含 Agent）知道「非 2 即等于没拦」 |

## 七、这次实测证明了什么

**它证明的不是「我写了一个能拦住的 hook」，而是——**

> **一道门禁，不实跑一遍，就无法知道它到底有没有生效。**
> **而失效的那三种形态，全都不报错。**

这与 `Rein Harness Engineering` 设计文档里那条判据完全一致：

> **一切不可被机器验证的约束，在 Agent 执行中都是无效约束。**

**本次是这条判据在一个真实门禁上的第一次实证：它原本无效，而自证测试把它抓出来了。**
